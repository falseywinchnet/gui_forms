# Computational CRC suitability for owned PNG

2026-10-20. The owner asked the PNG implementation chat to determine suitability
computationally, independently of the sibling's theoretical findings. This is
an experiment, not a production checksum switch or a claim of universal
optimality. The production `png_crc32` remains the existing slicing-by-eight
implementation.

`crc_kernels.cpp/.hpp` are first-party experiment sources copied from the sibling
worktree at `3a0ce443` (`codex/crc-algebra-study`), unchanged. Their slicing,
braiding, independent bit oracle and shared combination operator are described
in that branch's `experiments/crc-algebra-study/README.md`. No external CRC
implementation is copied into production.

`compact.cpp` is the PNG chat's C++ implementation of the sibling's exact
reciprocal degree-261 circuit:

```text
a = s[n-52] XOR y[n-12]
b = input[n] XOR y[n-209]
y[n] = a XOR y[n-150]
s[n] = a XOR b
```

It measures 32-, 64- and 128-bit polynomial scaling and the proposed four-step,
32-bit quartet schedule. Every call includes initialization, seed injection,
52 zero-word updates, history extraction, terminal reduction and exact live
byte tails. The terminal map uses a shared immutable 4 KiB table generated by
polynomial arithmetic at compile time. No input is mutated and no kernel
allocates. Ring boundaries are wrapped explicitly, without sentinel overreads.

The quartet has thirteen statically named auxiliary values. Contiguous accesses
are separated from ring splits before the arithmetic, and inlining is required
at those private helpers. Earlier measured lowerings are preserved: the default
compiler kept helper calls, and merely inlining an indexed auxiliary array
still left it in memory. Neither established the proposed register schedule.
The recorded assembly, not the C++ spelling, determines what was achieved.

A separately implemented direct degree-300 control uses the reflected multiple
with delays 145, 183, 211 and 300. This is a transparent recurrence control derived
from the construction in [Chorba, section III](https://arxiv.org/html/2412.16398v1),
not the deployed Chorba implementation and not a claim to outperform it. The
polynomial orientation is checked by full IEEE CRC comparisons. Both controls
use the same terminal-reduction implementation.

`study.cpp` checks complete CRCs against pinned upstream zlib and an independent
MSB-register bit oracle, including random seeds, 16 alignments, exact allocation
tails, split calls, constant messages, the standard check value, and independent
segments combined with a shared prepared shift operator. Combining segments is
verified algebraically/computationally; thread-pool throughput is not measured.
ASan, UBSan and LSan instrument the candidates and pinned oracle with no leak
suppression in this experiment.

The comparison includes small headers, synthetic spans through 1 MiB, actual
chunk boundaries from six generated 256×256 PNGs and the repository's red-pixel
asset. PNG trials replace only the checksum called by the decoder; filtering,
inflate and output representation remain identical for every CRC candidate.
The 32 KiB hybrid boundaries are explicit ablations, not universal crossover
claims. Native upstream zlib uses the M4's CRC opcode; a separately compiled
`-U__ARM_FEATURE_CRC32` control measures its generic implementation. The native
control is not eligible under the owner's portable-algorithm constraint.

Calibration targets 25 ms per batch, followed by rotating candidate order,
two warmup rounds and seven retained rounds. CSVs include medians, full ranges
and paired ratios. Source/pin/workload digests, commands, compiler, host and
load-average snapshots accompany results. These are warm, single-thread trials
on the M4; x64 SSE2/no-AVX is assembly inspection only. Host scheduling noise,
cold-cache behavior, simultaneous decode workloads and deployed Chorba remain
limits on selection. No narrow timing win certifies global optimality.
