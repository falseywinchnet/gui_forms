## Design (in force)

- **Data.** `MaterialFillKind::procedural` (appended) and `MaterialFillLayer::procedural`, a
  `ProceduralFill` (new header `include/gui_forms/surface_material/procedural_fill/`): pattern,
  32-bit seed, tile (logical units), strength, and the colours ground, figure, accent and bloom.
  Themes supply parameters only; the generators are built in.
- **Generation.** `src/core/engine/primitives/procedural/`: integer value noise (lowbias32 hash,
  16.16 fixed-point lattice, periodic over the tile), with no floating point in the pixel loops,
  so the bytes are identical on every host. The tile is square, round(tile × scale) device pixels;
  lattice periods are fixed in logical units, so each scale is generated, never resampled. The
  fresco is generated at the box's device size: a three-stop vertical gradient (ground, figure,
  accent) plus three seeded broad blooms of `bloom`.
- **Variant seam.** Each procedural fill asks for its tile through `EnginePrimitive::image_variants`
  (`ImageVariantRequest::procedural` set). The part table never generates on demand: it queues the
  tile, and the window's engine_idle frame generates one tile per idle frame (before keyframes).
  Until the tile is ready, the fill draws its ground as a solid (the "solid pair" placeholder).
- **Staleness.** A raster drawn with a placeholder records the table's procedural generation; it
  stops being current when a tile is made, and the window damages each record whose raster awaited
  one (as damage_backplane_readers does).
- **Cost.** Each pattern declares its generation cost per device pixel (measured, `--measure`); a
  tile whose generation estimate exceeds `maximum_material_bake_nanoseconds` refuses the material
  (built-in recipe, counted). Compositing a tile costs `costs.image` per destination pixel.
