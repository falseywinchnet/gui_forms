# Native CI timing and publication correction

**GIVEN:** the owner requires ordinary builds within five minutes, reuse across
PR/merge, and independent publication of each passing platform.

**MEASURED baseline:** Actions run `37754166288`, main `4e126d6`, and PR run
`37753375774`, head `42718cd`. Both commits have the same complete tree
`07d9b973487a8f7eb5c7d46dec4f773a25214ef1`. Durations below are job/step API
timestamps, excluding queue time.

| Platform | PR job | Main job | Main cold cache proof | Main toolkit + text checks |
|---|---:|---:|---:|---:|
| macOS arm64 | 5m18s | 56s | reused | reused |
| Linux x64 | 11m11s | 16m21s | 526s | 259s + 150s |
| Linux arm64 | 2m05s | 14m35s | 435s | 244s + 131s |
| Windows x64 | 3m35s | 21m20s | 592s | 287s + 219s |

**OBSERVED causes:**

- GitHub assigned newer runner images to main on Windows/Linux. PR images were
  `20260927.*`; main images were `20261004.*`. Image revision participated in
  both compiler and environment identities, defeating exact validation reuse.
  macOS retained its image and reused the PR receipt successfully.
- Main could not use PR-scoped Actions caches directly. It restored older main
  object caches, missing 235–251 compilations on Windows/Linux. Exact-tree
  artifact promotion avoids this branch-cache boundary without relaxing ccache.
- Cold proof depended on the environment and every CMake file. It repeated a
  multi-build experiment before ordinary native validation, costing 7–10 minutes.
- The publisher waited for the whole matrix. The Mac cache was ready at
  09:06:03 UTC; publication did not start until 09:26:26 UTC.
- Each fresh linkage configure fixture fetched miniaudio separately. The two
  accepted/rejected configure tests took 35–43 seconds combined in PR CI.

**Implemented:** weekly/manual Linux cache proof; exact-tree artifact promotion
before tool installation; retained producer environment and digest provenance;
independent per-platform publication with race-safe release creation and no
asset replacement; shared pinned miniaudio source for the two configure fixtures.
Native and installed consumer checks are retained. Partial releases do not
assert that absent platforms passed.

**Local validation:** archive promotion and publisher fixtures cover failed jobs,
changed actual trees, forks, expired/corrupted artifacts, source-tag mismatch,
producer identity, unchanged object bytes, concurrent release creation, and
refusal to replace different published bytes. Actionlint 1.7.12 validates both
workflows. Existing application/text/audio accepted and static-Core rejection
tests pass, together with the consumer executable. The unrelated existing Mac
manifest symlink test cannot run on this Windows session (WinError 1314); its
Linux CI job remains required and unchanged.

**Source review:** changed Python functions, four new Python tool/test files,
both workflow changes, and the CMake preload addition were reviewed against the
complete `planning/PROGRAMMING_HOUSE_STYLE.md`: explicit types, named behavior,
bounded discovery, stream lifetime, validation before mutation, failure cleanup,
publication races and no repeated dependency fetch. No violations identified in
that changed scope. Legacy helper code and vendored dependencies are not claimed
wholly compliant. Hosted timing acceptance must be measured on the new run;
baseline subtraction alone is not a result.

## First hosted trial and follow-up

**REJECTED performance trial:** run `37758529105`, commit `6d6f3cd`. All native
checks passed, but Linux x64 and macOS exceeded the owner's five-minute target.

| Platform | Native job |
|---|---:|
| Windows x64 | 4m25s |
| Linux arm64 | 1m42s |
| macOS arm64 | 5m15s |
| Linux x64 | 10m10s |

**MEASURED:** Linux x64 restored the older main tree
`f3e1054349fea60ffd83e1f61f24790cd4d9742e`, incurred 246/705 cache misses,
and spent 392 seconds in the primary toolkit stage plus 174 in development text.
The actual test portions were only 11 and 7 seconds. Mac had 0/703 misses;
its tool installation took 46 seconds, and timed native display/visibility
tests remain intentionally exercised in both baseline and development profiles.

**Implemented follow-up:** fresh builds can seed from a recent successful
same-compiler platform artifact across branches, while always running current
source tests. A seed never changes input identity or leaves a reused-validation
marker. Primary builds also reuse cached miniaudio source instead of fetching
again when FetchContent stamp files are absent. Homebrew automatic cleanup and
metadata updates are disabled for the explicit supported tool installation;
the exact LLVM version check remains.

**MEASURED promotion proof:** the actual Linux arm64 Actions archive from the
first trial was validated and repacked locally. All 2,976 non-manifest regular
files retained identical bytes. Producer identity/provenance checks passed.
The two additional seed tests verify retention of the new source identity,
mandatory native validation, and compiler mismatch rejection. Changed scope
review additionally covers `tools/ci_build.py` and seed discovery/restoration.

**MEASURED second trial:** run `37760012173` reduced Linux x64 to 1m45s
with 0/705 misses and current-source tests passing. All platforms passed under
five minutes: macOS 4m26s, Windows 4m09s, Linux arm64 3m09s, Linux x64 1m45s.
Linux arm64 exposed a
71-second seed-discovery miss walking legacy receipts. Follow-up rejects old
receipt schemas before provenance queries and caps seed inspection at eight
recent platform candidates; absence still falls back to ordinary compilation.
