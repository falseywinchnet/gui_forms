gui_forms::ButtonBase
=====================

.. cpp:namespace:: gui_forms

.. cpp:class:: ButtonBase : public Control

   ``#include <gui_forms/controls/button_base/button_base.hpp>``

   The common base of every clickable control: text, image, input and the click.

   :cpp:class:`ButtonBase <gui_forms::ButtonBase>` supplies what :cpp:class:`Button <gui_forms::Button>`, :cpp:class:`DropDownButton <gui_forms::DropDownButton>`, :cpp:class:`CheckBox <gui_forms::CheckBox>`,
   :cpp:class:`RadioButton <gui_forms::RadioButton>` and :cpp:class:`LinkLabel <gui_forms::LinkLabel>` share: a caption with an optional mnemonic, an
   optional image, focus, pointer and keyboard activation, command binding and the
   :cpp:func:`clicked <gui_forms::ButtonBase::clicked>` event. You normally create one of those concrete controls rather than
   a :cpp:class:`ButtonBase <gui_forms::ButtonBase>`; refer to ``ButtonBase&`` when one handler serves several kinds of
   button, because :cpp:func:`clicked <gui_forms::ButtonBase::clicked>` passes the control that was activated.

   *Status:* stable. *Windows Forms counterpart:* ``ButtonBase``.

   :Parameters:

      **stable_id** : ``StableId``
         Identity of the control, unique within its window. Logs, automation and
         semantic actions address the control by this ID. A bound :cpp:class:`Command <gui_forms::Command>`
         receives it as the invocation's source.

      **text** : ``std::string``, default ``{}``
         Caption. ``&`` marks the next character as the mnemonic, so ``"&Save"``
         responds to Alt+S; write ``&&`` for a literal ampersand. A ``\n`` starts a new
         line.

   :Properties:

      **command_connected** : ``bool``, read-only
         Whether a :cpp:class:`Command <gui_forms::Command>` is currently bound with ``bind``.

      **text** : ``std::string``, default ``""``

         raises :cpp:func:`text_changed <gui_forms::ButtonBase::text_changed>`.

      **font** : ``FontSpec``, default ``FontSpec{FontRole::control, 12.0, 400, false, 0.24}``
         Font used to measure and paint the caption. It is scaled by the window's
         text scale. An invalid specification throws ``std::invalid_argument``.

      **text_line_spacing** : ``double``, default ``1.25``
         Line height of a multi-line caption, as a multiple of the font size. It
         must lie between 0.75 and 3.0, or the setter throws
         ``std::invalid_argument``.

      **style** : ``BasicControlStyle``

         call :cpp:func:`set_style <gui_forms::ButtonBase::set_style>` this is the theme's basic style and the control paints
         from the theme's visual recipes; after :cpp:func:`set_style <gui_forms::ButtonBase::set_style>` it paints the classic
         relief in the given colours. :cpp:func:`clear_style <gui_forms::ButtonBase::clear_style>` returns to the theme.

      **has_style_override** : ``bool``, read-only

      **visual_recipes_override** : ``std::optional<ControlStateRecipes>``, read-only

         ``std::invalid_argument``.

      **image** : ``ImageId``, default ``ImageId{}``
         An image from the window's image registry, drawn with the caption. Setting
         it clears :cpp:func:`image_index <gui_forms::ButtonBase::image_index>` and :cpp:func:`image_key <gui_forms::ButtonBase::image_key>`. While the control is in a window,

         shows the list's hot, pressed, selected and disabled variants as its state

         Key into :cpp:func:`image_list <gui_forms::ButtonBase::image_list>`. Setting it clears :cpp:func:`image <gui_forms::ButtonBase::image>` and :cpp:func:`image_index <gui_forms::ButtonBase::image_index>`. The

      **image_alignment** : ``ContentAlignment``, default ``ContentAlignment::middle_center``
         Where the image sits when :cpp:func:`text_image_relation <gui_forms::ButtonBase::text_image_relation>` is ``overlay`` or there is

         Where the caption, or the caption and image together, sit inside the

      **clicked** : ``Event<ButtonBase&>``
         Raised when the control is activated: by a primary-button click, by Space

   .. rubric:: Notes

   Pointer input: pressing the primary button gives the control focus and draws
   it pressed. Moving off it while the button is held releases the pressed look,
   and moving back restores it. Releasing over the control raises :cpp:func:`clicked <gui_forms::ButtonBase::clicked>`;
   releasing elsewhere does nothing. If focus validation refuses to let focus
   leave the current control, the press is consumed and no click follows.

   Keyboard input: Space or Enter draws the focused control pressed, and
   releasing the same key raises :cpp:func:`clicked <gui_forms::ButtonBase::clicked>`. Auto-repeat does not repeat the
   click, and losing focus while the key is held cancels it. Because the focused
   control handles Enter itself, Enter activates the focused button rather than
   the window's accept button. Alt with the mnemonic letter activates the
   control from anywhere in the window, through the same validation as
   :cpp:func:`perform_click <gui_forms::ButtonBase::perform_click>`; when several controls share a letter, repeated presses cycle
   through them in tab order.

   The focus rectangle appears only while the window shows keyboard focus cues,
   so a mouse click focuses the button without drawing it.

   The control publishes the accessibility role ``button``. Its name is the
   accessible name, or else the caption without the mnemonic marker. It offers
   the actions focus and press; press runs :cpp:func:`perform_click <gui_forms::ButtonBase::perform_click>`. With an
   :cpp:func:`expanded_state <gui_forms::ButtonBase::expanded_state>` it also reports expanded and offers expand or collapse, and
   those actions raise :cpp:func:`clicked <gui_forms::ButtonBase::clicked>` without changing :cpp:func:`expanded_state <gui_forms::ButtonBase::expanded_state>`, so the
   application updates it in its handler. A ``visual_status`` of pending or invalid
   is reported as busy or invalid.

   The preferred size fits the caption and image plus :cpp:func:`content_padding <gui_forms::ButtonBase::content_padding>`, and is
   at least 24 high; a requested width or height takes precedence.

   .. rubric:: Examples

   Several kinds of button can share one handler, because :cpp:func:`clicked <gui_forms::ButtonBase::clicked>` passes the
   control that was activated:

   .. code-block:: cpp

      struct Toolbar final : gf::Component {
          std::shared_ptr<gf::Button> bold =
              gf::make_control<gf::Button>(gf::StableId("format.bold"), "&Bold");
          std::shared_ptr<gf::LinkLabel> help =
              gf::make_control<gf::LinkLabel>(gf::StableId("format.help"), "Formatting help");
          std::string last;

          Toolbar() {
              gf::on((*bold).clicked(), *this, &Toolbar::on_click);
              gf::on((*help).clicked(), *this, &Toolbar::on_click);
          }
          void on_click(gf::ButtonBase& source) {
              last = std::string(source.stable_id().value());
          }
      };

      void example() {
          Toolbar toolbar;
          (*toolbar.help).perform_click();   // toolbar.last is now "format.help"
      }

   Bind a button to a command. The button is enabled only while the command is,
   and a click executes it:

   .. code-block:: cpp

      gf::Command save("file.save", "Save");
      std::shared_ptr<gf::Button> button =
          gf::make_control<gf::Button>(gf::StableId("file.save"), "&Save");
      (*button).bind(save);
      save.set_enabled(false);    // the button is now disabled
      save.set_enabled(true);
      (*button).perform_click();  // executes save once

   .. rubric:: Extension points

   .. cpp:function:: virtual void bind(Command& command)

      ``bind(Command&)`` connects the control to a command, replacing any earlier
      command. The control's enabled state follows the command, a check box's
      checked state and a button's ``selected`` state follow a checkable
      command, and each activation executes the command once. The command
      runs as a :cpp:func:`clicked <gui_forms::ButtonBase::clicked>` handler connected by ``bind``, so handlers you
      connected earlier run before it. The control borrows the command; a
      disposed command is never invoked. Binding a disposed command throws
      ``std::invalid_argument``.
