gui_forms::ApplicationWindows
=============================

.. cpp:namespace:: gui_forms

.. cpp:class:: ApplicationWindows final

   ``#include <gui_forms/application/application.hpp>``

   A weak handle to the windows of a running application: open and destroy windows while it runs, and ask where things are on the desktop.

   ``ApplicationWindowHandle::windows`` returns it from any ready window's
   handle. Use it when the set of windows changes while the program runs, for
   example a tool panel torn out into its own window and docked back later. It
   also answers the desktop questions such a window needs: where the pointer
   is, which of the application's windows is under a point, and what the
   monitors' work areas are. Coordinates are desktop logical units: origin at
   the top left of the primary monitor, y downwards, the same units as
   ``ApplicationWindowHandle::frame``.

   Each request returns a status instead of throwing. A host that cannot do
   something reports :cpp:enumerator:`HostServiceError::unsupported <gui_forms::HostServiceError::unsupported>`; ask :cpp:func:`capabilities <gui_forms::ApplicationWindows::capabilities>` for
   :cpp:enumerator:`HostCapability::runtime_windows <gui_forms::HostCapability::runtime_windows>`, ``window_frames``, ``screen_pointer``,
   ``window_at_point`` and ``window_ordering`` first.

   :Properties:

      **active** : ``bool``, read-only
         Whether the run is live and the caller is on its UI thread.

      **capabilities** : ``HostCapabilities``, read-only
         The host's capabilities for this run; an empty set when inactive.

      **pointer_position** : ``HostScreenPointResult``, read-only
         The pointer's position in desktop logical units, wherever it is.

      **monitors** : ``HostMonitorResult``, read-only
         The monitors with their frames and work areas in desktop logical units.

      **window_count** : ``std::size_t``, read-only
         The number of live windows in the run, including any opened but not yet
         ready.

   .. rubric:: Notes

   Desktop logical units are exact on macOS. Windows and X11 address their
   desktops in device pixels; there each monitor keeps its device origin and
   its extent is divided by its scale, so with one scale everywhere the
   mapping is a plain division and with mixed scales a monitor scaled above 1
   leaves a gap to its right or below (see
   ``gui_forms/host/windowing/desktop_coordinates.hpp``).

   Window identities are assigned in opening order and never reused within a
   run, so a destroyed window's identity cannot name a later window, even one
   opened under the same stable id.

   On X11 a window manager decides where windows go: a frame request is a
   request, and the window manager may adjust it or, under some compositors
   running XWayland, ignore the position.

   .. rubric:: Examples

   Open a hidden tool window beside the main window, place it, then show it.
   This needs a native host, so it is compiled but not run:

   .. code-block:: cpp

      // compile only
      struct OpenPalette final {
          void operator()(gf::Window&, gf::ApplicationWindowHandle main) const {
              const gf::ApplicationWindows windows = main.windows();
              if (!windows.capabilities().supports(gf::HostCapability::runtime_windows)) return;
              gf::ApplicationWindow palette;
              palette.stable_id = "palette";
              palette.owner_id = "main";
              palette.tool_window = true;
              palette.model = std::make_unique<gf::Window>(
                  gf::make_control<gf::Panel>(gf::StableId("palette.root")), gf::Size{240.0, 320.0});
              palette.options.title = "Palette";
              palette.options.initial_size = {240.0, 320.0};
              palette.options.initially_visible = false;
              const gf::ApplicationWindowOpenResult opened = windows.open_window(std::move(palette));
              if (!opened.status.accepted()) return;
              const gf::HostWindowFrameResult frame = main.frame();
              if (frame.status.accepted()) {
                  const gf::Rect beside{frame.frame.content.right() + 16.0, frame.frame.content.y,
                                        240.0, 320.0};
                  static_cast<void>(opened.window.request_frame(beside));
              }
              static_cast<void>(opened.window.show());
          }
      };

      void example() {
          gf::ApplicationWindowOptions options;
          options.title = "Editor";
          options.ready = OpenPalette{};
          gf::ApplicationResult result = gf::Application::run(
              std::make_unique<gf::Window>(gf::make_control<gf::Panel>(gf::StableId("editor")),
                                           gf::Size{640.0, 480.0}),
              std::move(options));
          static_cast<void>(result);
      }

   .. rubric:: Methods

   .. cpp:function:: ApplicationWindowOpenResult open_window(ApplicationWindow&& window) const

      Opens a window during the run. The entry follows the rules
      ``Application::validate`` applies to each window, and it must be owned by
      a live window of this run or be a tool window; a second primary window
      is refused. At most ``Application::maximum_windows`` windows are live at
      once. The new window's ``ready`` callback runs before :cpp:func:`open_window <gui_forms::ApplicationWindows::open_window>`
      returns. A refusal found before the native request (an invalid entry, an
      unknown owner, a duplicate stable id, the window limit) leaves the entry
      unchanged; after that the entry is consumed.

   .. cpp:function:: HostServiceStatus destroy_window(const ApplicationWindowHandle& window) const

      Closes and destroys a window without asking its ``closing`` callback:
      the program has decided. Its ``closed`` callback runs before
      :cpp:func:`destroy_window <gui_forms::ApplicationWindows::destroy_window>` returns, and its handle stops working. The primary
      window, and a window that still owns open windows, are refused with
      :cpp:enumerator:`HostServiceError::invalid_argument <gui_forms::HostServiceError::invalid_argument>`.

   .. cpp:function:: ApplicationWindowAtResult window_at(DesktopLogicalPoint point) const

      The application's window that is topmost at a desktop point, counting
      its title bar and borders where the host can. ``found`` is false when the
      desktop or another application's window is there.
