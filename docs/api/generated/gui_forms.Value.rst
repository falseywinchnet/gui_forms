gui_forms::Value
================

.. cpp:namespace:: gui_forms

.. cpp:class:: template <typename T> Value final : public Component

   ``#include <gui_forms/value/value.hpp>``

   A shared scalar that the application owns and controls can bind to.

   A :cpp:class:`Value <gui_forms::Value>` holds one number, ``bool`` or enumeration, such as a volume, a
   "wrap lines" setting or a selected mode. Several controls can bind to the
   same value with ``CheckBox::bind``, ``RangeControl::bind`` or
   ``ChoiceGroup::bind``, and the rest of the application observes it through
   :cpp:func:`changed <gui_forms::Value::changed>`. Writing an equal value does nothing, so two bound controls never
   echo a change back and forth. Keep strings and objects in your own model;
   :cpp:class:`Value <gui_forms::Value>` accepts only scalar types, and the compiler rejects others.

   :Parameters:

      **initial** : ``T``, default ``T{}``
         The starting value, ``T{}`` by default. A floating-point value must be
         finite; NaN or infinity throws ``std::invalid_argument``.

   :Properties:

      **get** : ``T``, read-only
         The current value. Reading it is always allowed, also after disposal.

   :Events:

      **changed** : ``Event<T>``
         Raised after a new value is committed, with that value. An exception from
         a handler propagates to the caller of :cpp:func:`set <gui_forms::Value::set>`, but the new value is already
         stored.

      **validating** : ``Event<T>``
         Raised by :cpp:func:`set <gui_forms::Value::set>` before a new value is committed, with the candidate. A
         handler rejects the candidate by throwing; the exception reaches the
         caller of :cpp:func:`set <gui_forms::Value::set>` and the value stays as it was. Bound controls use this to
         apply their own limits. It is not raised for an equal value.

   :Inherited:

      It also has every member of :cpp:class:`Component <gui_forms::Component>`: geometry, layout, visibility, focus, input routing, painting and disposal.

   .. rubric:: Notes

   A value is a :cpp:class:`Component <gui_forms::Component>`. Disposing it, or destroying it, ends every
   connection to :cpp:func:`changed <gui_forms::Value::changed>` and :cpp:func:`validating <gui_forms::Value::validating>`, including those of bound controls,
   which keep the last state they showed. After disposal, :cpp:func:`set <gui_forms::Value::set>` and
   :cpp:func:`validate_candidate <gui_forms::Value::validate_candidate>` throw ``std::logic_error``. Destroying a value from inside
   one of its own :cpp:func:`changed <gui_forms::Value::changed>` handlers is allowed; the remaining handlers are
   skipped.

   While :cpp:func:`validating <gui_forms::Value::validating>` or :cpp:func:`changed <gui_forms::Value::changed>` handlers run, a further :cpp:func:`set <gui_forms::Value::set>` with the same
   value does nothing and one with a different value throws ``std::logic_error``.
   This stops observers that correct each other from looping; to make a
   follow-up change, do it after the notification returns.

   Notifications are synchronous on the thread that calls :cpp:func:`set <gui_forms::Value::set>`. Use a value on
   the UI thread of the windows whose controls bind to it. It never starts a
   timer or schedules work.

   .. rubric:: Examples

   Observe a setting, and see an equal write do nothing:

   .. code-block:: cpp

      enum class Mode { edit, preview };

      struct StatusBar final : gf::Component {
          int updates = 0;
          void on_mode(Mode) { ++updates; }
      };

      void example() {
          gf::Value<Mode> mode(Mode::edit);
          StatusBar status;
          gf::on(mode.changed(), status, &StatusBar::on_mode);
          mode.set(Mode::preview);   // status.updates == 1
          mode.set(Mode::preview);   // equal: nothing is raised
      }

   Reject out-of-range values with a :cpp:func:`validating <gui_forms::Value::validating>` handler:

   .. code-block:: cpp

      struct VolumeLimit final : gf::Component {
          void check(int candidate) {
              if (candidate > 100) throw std::out_of_range("volume above 100");
          }
      };

      void example() {
          gf::Value<int> volume(50);
          VolumeLimit limit;
          gf::on(volume.validating(), limit, &VolumeLimit::check);
          volume.set(80);            // accepted
          try {
              volume.set(120);       // rejected before it is stored
          } catch (const std::out_of_range&) {
          }
          // volume.get() == 80
      }

   .. rubric:: Methods

   .. cpp:function:: void validate_candidate(const T value) const

      Runs the same checks and :cpp:func:`validating <gui_forms::Value::validating>` handlers as :cpp:func:`set <gui_forms::Value::set>` without storing
      anything, so a control can find out whether a change would be accepted
      before it changes its own state. It throws as :cpp:func:`set <gui_forms::Value::set>` does.

   .. cpp:function:: void set(const T value)

      Changes the value. An equal value does nothing. Otherwise :cpp:func:`validating <gui_forms::Value::validating>` is
      raised, the value is stored and :cpp:func:`changed <gui_forms::Value::changed>` is raised. Throws
      ``std::invalid_argument`` for a non-finite floating-point value and
      ``std::logic_error`` when the value is disposed or when called with a
      different value while the value's own handlers are running.
