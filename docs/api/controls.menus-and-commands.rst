Menus and commands
==================

Commands, menu strips and context menus.

.. list-table::
   :class: autosummary longtable
   :widths: 35 65

   * - :cpp:class:`MenuStrip <gui_forms::MenuStrip>`
     - A window's menu bar: a row of top-level menus such as File, Edit and View.
   * - :cpp:class:`ToolStrip <gui_forms::ToolStrip>`
     - A command strip of buttons, labels, separators and drop-down buttons.
   * - :cpp:class:`RibbonGallery <gui_forms::RibbonGallery>`
     - A ribbon gallery: a grid of image items in categories, in the ribbon or as a drop-down.
   * - :cpp:class:`StatusStrip <gui_forms::StatusStrip>`
     - A status bar laid out as a strip of labels along the bottom of a window.
   * - :cpp:class:`QuickAccessToolbar <gui_forms::QuickAccessToolbar>`
     - The Quick Access Toolbar of a ribbon window: a small strip of command buttons the user chooses.
   * - :cpp:class:`ToolStripPanel <gui_forms::ToolStripPanel>`
     - A band along one edge that holds ToolStrips.
   * - :cpp:class:`ToolStripContainer <gui_forms::ToolStripContainer>`
     - Four ToolStripPanels around a content panel.
   * - :cpp:class:`BindingNavigator <gui_forms::BindingNavigator>`
     - A ToolStrip that moves through a BindingSource.
   * - :cpp:class:`Ribbon <gui_forms::Ribbon>`
     - A ribbon: the File tab and core tabs over a command plane of groups.
   * - :cpp:class:`ContextMenu <gui_forms::ContextMenu>`
     - A popup menu of commands that the application opens at a point, such as on a right-click.
   * - :cpp:class:`Command <gui_forms::Command>`
     - An application action, such as Save or Copy, shared by every button, menu item and shortcut that triggers it.
   * - :cpp:class:`GalleryCommand <gui_forms::GalleryCommand>`
     - The value command of a gallery: a shared Command, the chosen item, and live preview.

.. cpp:struct:: RibbonCommandSpec final

   ``#include <gui_forms/controls/ribbon/ribbon.hpp>``

   One command record. ``stable_id`` is unique within the ribbon (across tabs, groups and commands) and names the command in events, semantics and the published anatomy. A button, toggle or split takes its text (when ``text`` is empty), enabled, visible and checked state from its required ``command``, and runs it on a click; a drop-down's command is optional. ``text`` may carry a mnemonic ("&Paste"). Labels are always shown (owner decision 6); a small command with an image may leave its label out (``show_label`` false: an authored icon-only command, decision 30). ``drop_down`` is the menu of a split or drop-down command. A hosted command's ``text`` is its control's accessible name (and a check box's caption); ``choices`` are a combo box's items and ``width`` its width in logical units (zero for the default). A gallery command's ``gallery`` is an in-ribbon RibbonGallery the application made and configured; the ribbon adds it as its child and sets its column count.

   .. cpp:member:: std::string stable_id

   .. cpp:member:: RibbonCommandKind kind

      Default: ``{RibbonCommandKind::button}``.

   .. cpp:member:: RibbonCommandSize size

      Default: ``{RibbonCommandSize::large}``.

   .. cpp:member:: std::shared_ptr<Command> command

   .. cpp:member:: ImageId image

   .. cpp:member:: bool show_label

      Default: ``{true}``.

.. cpp:struct:: ToolStripItemSpec final

   ``#include <gui_forms/controls/tool_strip/tool_strip.hpp>``

   One item. ``stable_id`` is unique within the strip and names the item in events, semantics and the published anatomy. An item with a ``command`` takes its text (when ``text`` is empty), enabled, visible and checked state from it, and a click executes it. An item without one uses ``text``, ``enabled``, ``visible`` and the strip's own checked state. ``drop_down`` is the menu of a drop-down or split button and must be empty for other kinds. ``spring`` is honoured only by StatusStrip, on labels: spring labels share the width the other items leave. A hosted item (combo box, text box, progress bar) takes no command, menu or check. Its ``text`` is the hosted control's accessible name, ``choices`` are a combo box's items, and ``width`` its width in logical units (zero for the default: 120 for a combo box, 100 otherwise). Hosted items never move to the overflow menu, whatever their ``overflow``: a menu row cannot hold a control. The application reaches the control through combo_box(), text_box() or progress_bar(); it keeps its state while set_items keeps an item of the same ID and kind.

.. cpp:function:: std::string serialize_ribbon_state(const RibbonState& state)

   The stable text form, one entry per line, LF-terminated: gui_forms.ribbon_state 1 quick_access.placement=above_ribbon (or below_ribbon) ribbon.minimized=false (or true) quick_access.command=<command ID> (one line per ID, in order) <unrecognized entries, unchanged> Command IDs are written verbatim; an ID may not be empty or hold a line break or other control character. Throws std::invalid_argument for such an ID, a repeated ID, more than QuickAccessToolbar::maximum_commands IDs, or an unrecognized entry that holds a line break.

.. cpp:function:: RibbonState capture_ribbon_state(const QuickAccessToolbar& toolbar, bool minimized)

   The toolbar's part of the state, and its application to a toolbar. ``minimized`` is the Ribbon's, which applies it. Command IDs the toolbar does not declare survive apply and capture (the toolbar keeps them, inert); unrecognized entries are not the toolbar's, so capture returns none and a caller that keeps them copies them from the state it loaded. Applying sets the toolbar's shown commands and placement, emitting placement_changed when the placement changes.
